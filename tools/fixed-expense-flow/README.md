# AIBoot 고정비 업무 흐름도 (읽기 전용)

고정비 업무가 **실제로 어디까지 자동으로 연결되어 있는지**를 클릭해서 확인하는 화면이다. 새 관리 시스템이 아니며 실행기·시트·웹훅·스케줄러를 바꾸지 않는다.

## 여는 방법 (이 PC)

```powershell
cd tools\fixed-expense-flow
node build-evidence.mjs --repo C:\Users\admin\Desktop\github\AIBoot   # 작업 스케줄러가 실행하는 운영 폴더
start index.html                                                     # 브라우저로 열기(서버 불필요)
```

- `build-evidence.mjs`는 **읽기만** 한다: 운영 폴더의 `runner.mjs`·`docs/FIXED-EXPENSES-V1.md`, `%USERPROFILE%\.aiboot\`의 `logs`·`ledger.json`·`reports`. 네트워크·Google API·`config.json`은 쓰지 않는다.
- 결과는 같은 폴더의 `evidence.local.js`(Git 제외)에만 저장된다. 웹훅 주소·토큰·스페이스 ID·메시지 ID·금액·메시지 본문은 들어가지 않는다.
- 화면의 실행 상태는 실시간 조회가 아니라 **이 파일을 만든 시각 기준**(`마지막 확인 기준`)이다. 새로 보려면 다시 실행한다. 파일이 없으면 실행 관련 상태는 모두 `미검증`으로 나온다.

## 화면 구성

| 영역 | 내용 |
|---|---|
| 질문으로 찾기 | 검증 질문 7개 → 오른쪽 패널에 답과 근거 |
| 업무 흐름 | ① 원본 데이터(JP매월 지출 · AIBoot_데일리마감 · 규칙 문서 · Gmail · Chat 스페이스) → ② 수집 → ③ 일정 계산 → ④ Codex·Antigravity → ⑤ 검증 → ⑥ Google Chat |
| 업체별 연결 상태 | 23개 업체 × 4단계(납부 일정 / 청구서 자동 확인 / 지출결의 표시 / 실제 지급 확인) |
| 누락 추적 | 업체를 고르면 “원본 → 활성 → 예정일 → 7일 창 → AI 판단 → 검증 → 발송” 중 어디서 빠졌는지 순서대로 표시 |
| 조사에서 확인한 차이 | 코드와 문서·운영이 다른 지점(근거 포함) |

## 상태 기준

`연결 확인`(실제 조회·실행 성공 근거) · `부분 연결` · `미연결`(읽는 기능 없음) · `수동 처리` · `조회 실패`(기능은 있으나 최근 실패) · `미검증`(근거 없음) · `비활성`. 코드에 기능이 있다는 것만으로 `연결 확인`을 주지 않는다.

`build-evidence.mjs`는 실행할 때마다 실행기 코드를 다시 확인한다(읽기 범위, Gmail 미연결, 이지화물 제외, 읽기 전용 호출 등). 코드가 바뀌어 확인이 깨지면 화면 상단에 재검토 경고가 뜬다. 업체별 예정일은 실행기의 `fixedSchedule()` 함수를 그대로 실행해서 계산한다.

## 파일

- `flow-data.js` — 구조·설명·업체 규칙(커밋 대상, 비밀값 없음). 업체·규칙이 바뀌면 `docs/FIXED-EXPENSES-V1.md`와 함께 고친다.
- `build-evidence.mjs` — 이 PC 실행 근거 수집(읽기 전용).
- `index.html` — 화면(외부 라이브러리 없음).

## 다른 분야로 넓히기

계약서·라이센스·복지·정기 업무도 같은 형식으로 `sources`·`stages`·항목 목록을 가진 데이터 파일을 추가하고, `build-evidence.mjs`에 해당 코드 확인 항목을 넣으면 된다. Archify(tt-a1i/archify)는 에이전트 스킬 설치와 다이어그램 생성 과정이 필요하다. 반면 이 화면은 이 PC의 로그·원장·코드로 상태를 다시 계산해야 하므로 의존성 없는 단일 HTML로 만들었다.

## 2026-11-05 화면 개선 (기존 기능 보존)

- 상단에 요약 지표를 배치하고 `업체별 기능 연결 상태`의 네 항목이 **업무 완료 여부가 아닌 각각 독립된 연결·판독 기능**임을 명시.
- `지출결의 표시 읽기` = 시트의 연노랑 서식 판독 기능. **실제 전자결재 완료나 납부 확인을 뜻하지 않음.**
- `납부 일정 계산` = 규칙상 예정일 산출. 고지서 실제 납부일 확정 아님.
- 기존 여섯 단계 흐름 및 23개 업체 상세·누락 추적은 유지. 문제 목록·상태 기준은 오른쪽 정보 열로 정리.
- 상단 업무 분야 탭(고정비·복지·계약서·라이센스·정기 업무·기타 업무) 추가. **고정비만 기존 운영 로그 증거**를 통해 상태를 계산. 다른 분야는 관련 PR의 알려진 원본·업무 규칙을 보여주되, 이 도구에서 실제 조회 근거를 수집하지 않았으므로 상태·건수는 전부 `실조회 미검증`으로 표현. 범위를 늘린 것과 실제 연결 성공을 혼동하지 않는다.
- 수유 수도요금 격월·매장 안전관리자 상세 회차 문제는 별도의 실행기 수정 PR로 처리하며 **이 화면에서 정상화된 것으로 표시하지 않는다**. 실제 운영 코드 배포 및 샘플 테스트가 끝나면 `flow-data.js`의 경고 항목을 재확인 후 갱신.
- 읽기 전용 원칙, 개인 데이터/금액/토큰 제외, 사용자가 기존 시트에서 일하는 방식, 웹훅·스케줄러는 변경 없음.
