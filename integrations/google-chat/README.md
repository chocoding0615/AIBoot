# AIBoot — Google Chat 양방향 앱 준비

> **현재 상태: 코드 작성 및 숨김 기록 탭 생성 완료 / 회사 계정 Chat 앱 배포·웹훅 연결·실메시지 테스트 미실시**

## 구조

- **기존 `JP매월 지출`은 읽기 전용**: 업체 목록·금액·연노랑 지출결의 표시를 그대로 사용. 원본 집계 수식은 변경하지 않음.
- **Google Chat App (Apps Script)**: 사용자의 명시적 회차별 '완료' 또는 '업체 대기' 회신을 받고 기록하고 조회. Webhook만으로는 답장을 받을 수 없음.
- **기존 Google Chat incoming webhook**: 오전 09:30/오후 16:00 업무보고 발송 전용. 실사용 웹훅을 재발급하지 않고 기존 것을 Script Properties에 등록하는 방식.
- **`AIBoot_데일리마감`**: 기존 스프레드시트 안의 별도 **숨김 탭**, 작성/수정 없이 이벤트를 **추가 기록만**. 기존 비용 DB와 무관한 AI 내부 기록이므로 사용자의 원래 업무 방식은 그대로. 하루의 이벤트와 업체·사용회차별 가장 최근 상태를 구분.
- 2026-10 이지화물 종료: 새 업무에서 제외.
- 3~4개월 일괄 청구: 업체+사용기간을 한 단위로 명시, 실제 출금 미확인 상태를 미납으로 단정하지 않음.

## 보안: GitHub에 넣지 않는 값

**반드시 회사 Workspace 계정**으로 진행. `Script Properties`에서 아래 키를 설정한다.

| 키 | 값 |
|---|---|
| `SOURCE_SPREADSHEET_ID` | 기존 `[MS] AD_관리비 내역`의 Spreadsheet ID (기준서 참조) |
| `OWNER_EMAIL` | 회사 Workspace 사용자 이메일 |
| `CHAT_WEBHOOK_URL` | 사용자가 이전에 만든 **기존 Google Chat 웹훅 전체 URL**, 비밀로 저장 |

> 웹훅 URL에 키·토큰이 포함되므로 **GitHub, PR, 채팅 로그에 원문을 쓰지 말 것**. 과거 대화에서 URL의 실제 값은 확인되지 않았으며 자동 발견했다고 주장하지 않는다. 사용자가 직접 Script Properties에 설정해야 한다.

## 배포 체크리스트 (회사 계정)

1. `https://script.google.com/home/projects/create`에서 회사 Workspace로 새 Apps Script 프로젝트 생성.
2. `Code.gs`를 프로젝트에 붙여 넣고 Script Properties를 설정.
3. **회사 정책/권한 확인**: Google Cloud 프로젝트에서 Google Chat API 사용 설정과 App 설정이 허용되는지 확인. 관리자 차단 시 무리하게 우회하거나 개인 계정으로 만들지 않는다.
4. 숨김 `AIBoot_데일리마감` 탭은 회사 기존 문서에 이미 생성되어 있고 헤더 확인까지 완료. `initializeDailyLog()`는 **이미 있으면 변경 없이 종료**하도록 구현되어 있으므로 새로 만들 필요 없음. 기존 지출 DB와 `JP매월 지출`의 값·서식은 건드리지 않음.
5. Google Chat API의 Connection settings에서 `Apps Script` 및 테스트 배포 ID를 지정. Visibility는 회사 내 해당 사용자만. 테스트 DM에서 `도움말`로 응답 수신 확인.
6. 아래 **조회**를 먼저 검증하고, 업체·회차·증빙이 정확할 때만 `완료`를 입력.
7. **웹훅 보고는 나중에 활성화**: 테스트 공간이 회사 사용자 전용인지 확인 후 `previewMorningReport()`, `previewAfternoonReport()`의 반환 텍스트를 먼저 검토하고, `sendMorningReport()`, `sendAfternoonReport()`를 **실발송 허가 후** 테스트한다.
8. 마지막으로 근무일·공휴일·휴가 판단 및 트리거 중복방지, 실제 09:30/16:00 운용 요건을 검증한 뒤 정기 트리거를 만들 것. **현재 코드에는 트리거 생성/휴가 자동 판단 기능이 없음.**

## 대화 명령 (실험용 명시적 형식)

| 입력 | 결과 |
|---|---|
| `도움말` | 명령 안내 |
| `조회\|2026-11` | 해당 회차와 관련해 **기록이 존재하는 이벤트만** 요약 |
| `완료\|생각공장\|2026-09\|납부 완료 직접 확인` | **해당 사용회차만** 완료 기록 |
| `대기\|양주 전기료\|2026-07~2026-09\|2026-11-20\|업체가 3개월분 일괄 청구 예정` | 업체 자료 대기·다음 확인 날짜 기록 |

완료 명령은 실제 지급이 확실한 경우에만 사용. 연노랑 표시는 '지출결의 제출'일 뿐 `완료`로 자동 전환되지 않는다. 단순한 `처리했어`를 업체/회차 없이 추측하여 저장하지 않는다.

## 데일리 마감 탭 스키마

`기록시각 | 기록일 | 업체 | 사용회차 | 상태 | 다음확인일 | 메모 | 기록자 | 원문`

- 덮어쓰기 대신 **기록을 추가**한다. 같은 업체·사용회차의 최신 행이 현재 상태.
- 일괄 청구 회차는 `YYYY-MM~YYYY-MM` 형태로 구분.
- 2026-11-03 회사 기존 문서에 **숨김 탭만 실제 생성**, 헤더 확인 완료. 현재 기록은 0건. 앱 배포와는 별개이고 원본 금액/서식을 수정하지 않았다.
- 이 단계에서는 **사용자가 수동으로 상태를 고치기 위한 탭이 아님**. 조회·관리 주체는 AIBoot.

## 아직 미구현/미검증

- Google Chat 앱 실제 등록 및 회사 사용자 권한.
- 과거 웹훅 URL 설정·실발송. 기존 URL을 확인하지 못했으므로 코드에 포함하지 않음.
- 보고용 09:30/16:00 트리거, 주말·공휴일·반차·종일휴가 자동 판단, 중복발송 방지.
- 청구서 메일 자동 대조, 23개 업체 전체 실제 납부 회차 확인.
- Google Sheets 연노랑 서식을 읽어 업무 브리핑으로 통합하는 전체 로직.
- 기존 지출 시트에서 **비서 전용 로그로의 자동 회차 매핑**, 실제 지급 검증 자동화.
- 계정 정책에 따라 Chat의 `event.user.email`이 숨겨지면 앱이 보안상 거절하며, 관리자/테스터 환경에서 안전하게 다시 검증해야 함.
