# AIBoot 대화·제안 v1

운영 정책은 [CURRENT.md](../../CURRENT.md)를 따른다. 기본 동작은 로컬 미리보기이며, main 병합·운영 배포·실제 발송은 사용자 별도 승인 후 수행한다. 과거 오류와 검증 이력은 [PR #29](https://github.com/chocoding0615/AIBoot/pull/29)에 보존한다.

## 현재 동작

- 지정 공간의 본인 HUMAN 메시지만 수집한다. 메시지 ID 중복 방지와 독립 커서를 사용하며 기존 정기 보고의 원장·Chat 커서는 읽기만 한다.
- 질문에 필요한 연결 자료를 최신 조회한다. AI는 입력에 포함된 CURRENT·고정비 규칙 전문과 업무 자료만 사용하며 추가 파일·명령 조회를 요구하지 않도록 지시한다. 최근 10개 대화와 지난 7일 업무 맥락은 질문 해석용이고 현재 사실은 최신 자료의 출처 ID로 검증한다.
- 답변은 원본 사실·출처, 고정 허용 문구의 미실행 제안, 조회 실패를 구분해 저장한다. 알 수 없는 질문은 확인 질문으로 남기고 AI를 호출하지 않는다.
- 제안 후보는 AI 호출 없이 서로 다른 원본의 동일 대상·확정 날짜를 연결해 최대 3개 생성한다. 발송된 정기 보고·기존 후보와 중복을 제거한다. 보고 비교 자료가 없으면 보류한다. Chat 원문에서 대상·날짜를 추출하지 않으므로 Sheets와의 의미 기반 연결은 하지 않는다.
- 상태는 `%USERPROFILE%\.aiboot\assistant\state.json`에 원자적으로 저장한다. PID 잠금과 손상 검사로 중복 실행·초기화 덮어쓰기를 막는다. 재시작 시 생성 중 질문은 대기로, 발송 중 질문은 결과 불명으로 복원한다.
- 정기 업무의 완료 요청은 AI 없이 원본 업무명·행위·계산된 회차를 대조한다. 예: `법정의무교육 공지 완료했어` → 대상·회차·확인 코드 미리보기 → `완료 확인 코드 처리일 YYYY-MM-DD`. 이름·회차가 여러 개면 정확한 원본 업무명과 회차 기준일을 다시 요청한다. 확인은 24시간 안에 같은 설정의 본인이 해야 한다.
- 승인 후 행위별 이력은 기존 로컬 상태의 `completionHistory`에 저장한다. 업무ID(미지정이면 원본·규칙 기반 로컬 식별자), 회차, 행위, 실제 처리일, 처리자, 요청·확인 메시지 ID를 보존하며 Sheets에는 쓰지 않는다. 공지와 이수, 결의 작성과 납부, 갱신 검토와 계약은 구분한다. 다음 회차는 제외하지 않으며 원본 이력과 다르면 확인 필요로 남긴다.
- 대화 근거·제안에서는 확인된 동일 행위만 제외한다. **기존 정기 보고는 아직 이 로컬 이력을 읽지 않는다.** 보고 반복 추천 차단은 별도 승인한 최소 연동·운영 반영 이후에만 적용된다.

## 설정

기존 `%USERPROFILE%\.aiboot\config.json`, Chat 읽기 토큰, Sheets 인증과 `googleapis` 설치를 사용한다. 인증정보·웹훅·회사 자료를 저장소에 넣지 않는다. 로컬 설정과 상태 폴더는 사용자 전용 접근 권한으로 관리한다.

별도 `%USERPROFILE%\.aiboot\assistant.json`:

| 필드 | 값 |
|---|---|
| `space` | 사용자 승인 대화 공간 `spaces/…`. 업무 참조용 공간과 겹치면 차단 |
| `owner` | 본인의 canonical `users/숫자` |
| `startAt` | 사용자 승인한 최초 수집 시작 RFC3339 시각 |
| `maxDailyCalls` | `null`: 필요시 호출. 숫자 1~20: 선택적 일일 상한 |
| `deliveryApproved` | 기본 `false`. 실제 발송 승인 이후에만 `true` |
| `completionRecordingApproved` | 기본 `false`(미설정 포함). 완료 이력 저장 운영 승인 이후에만 `true`. 각 건의 명시적 확인도 필요 |

토큰 계정은 대화 공간 멤버여야 한다. 기존 웹훅 대상과 대화 공간이 일치해야 하며 새 공간·웹훅·스케줄러는 자동 생성하지 않는다.

## 보호와 실패 처리

- Antigravity는 질문이 있을 때만 호출한다. 세션은 `agentMode: ""`(default), `toolPermission: "strict"`, `useG1Credits: false`와 slash 확장 금지를 사용한다. 명령·파일 작업의 자동 승인을 허용하지 않으며 구독 초과 크레딧으로 전환하지 않는다.
- 프롬프트는 stdin에 UTF-8 NDJSON user 메시지 1개로 쓰고 닫는다. `--input-format stream-json --output-format stream-json`의 최종 result 구조화 결과만 받아 필수 필드·허용 문구·최신 근거를 검증한다. 자유 텍스트·진행 이벤트·부분 JSON으로 우회하지 않는다. 입력은 64,000 UTF-16 단위의 별도 문맥 예산을 적용하며 필수 정책은 자르지 않는다. 오래된 맥락·일부 근거를 제외하면 표시한다. 출력은 행/최종 결과 64,000바이트와 실행 시간을 제한하며 진행 이벤트를 누적하지 않는다. 기존 정기 보고의 argv 전달 방식은 변경하지 않는다.
- KST 09:00–11:15 / 15:30–17:45, 정기 보고 생성·발송·결과 불명 상태에서는 AI 생성·발송을 대기한다. 생성 중에도 보호 상태를 확인한다. 원장이 없거나 손상되면 중단한다. 질문 수집은 계속한다.
- 실패한 질문은 보존하고 자동 재시도하지 않는다. 구독 한도 오류만 당일 다른 AI 호출도 대기시킨다. 단일 형식·근거 오류는 다른 질문을 하루 전체 차단하지 않는다. 호출 횟수와 안전한 오류 유형·종료 코드를 기록한다.
- 실제 발송에는 사용자 승인, `--send`, `deliveryApproved: true`가 모두 필요하다. 발송 직전 원본을 재확인하며 결과 불명은 자동 재발송하지 않는다. 후보 자동 발송 경로는 없다.

## 실행

운영 승인 후 저장소 루트에서 실행한다.

```sh
node integrations/chat-assistant/cli.mjs --once
node integrations/chat-assistant/cli.mjs --once --propose
node integrations/chat-assistant/cli.mjs --loop
```

위 명령은 답변·후보를 로컬에만 저장한다. `--loop`는 60초마다 조회하며 AI 호출은 대기 질문이 있을 때만 발생한다. 질문·후보·오류는 로컬 상태에서 확인한다.

오프라인 테스트:

```sh
node --test integrations/chat-assistant/tests/*.test.mjs
```
