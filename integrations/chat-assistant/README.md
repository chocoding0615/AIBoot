# AIBoot 대화·제안 v1 — 운영 미반영

정책은 [CURRENT.md](../../CURRENT.md) 하나를 따른다. 정기 보고 실행기·웹훅 설정·원장·Chat 수집 커서는 변경하지 않는다. Apps Script 배포 없이 운영 PC가 Chat API를 조회하는 선택한 경로만 구현한다. main 병합·운영 PC 설치·실제 발송은 별도 사용자 승인 전 금지다.

## 동작과 재사용

- `core.mjs`: 지정 사용자(`sender.name`의 canonical `users/숫자`)의 HUMAN 메시지만 수집한다. 메시지 ID 중복 방지, 2분 겹침 조회, 모든 페이지 처리, 질문 저장 후 독립 커서 갱신을 사용한다. 짧은 질문도 수집한다. 메시지 수정은 같은 ID의 신규 질문으로 취급하지 않는다. 최초 수집은 명시한 `startAt` 이후부터이며, 삭제/보존기간 경과 메시지는 복원할 수 없다.
- `store.mjs`: `%USERPROFILE%\.aiboot\assistant\state.json`에 대기 질문·답변·최근 10개 메시지·지난 7일 조회 맥락·후보·처리 ID를 원자적으로 저장한다. 처리 ID와 후보 이력은 중복 방지를 위해 유지한다. 재시작 시 생성 중 질문은 대기로, 발송 중 질문은 결과 불명으로 복원한다. PID 잠금으로 중복 프로세스를 막고 손상된 상태를 빈 파일로 덮지 않는다. Windows에서는 해당 사용자만 접근하도록 폴더 ACL을 확인해야 한다.
- 질문의 업무 단어와 직전 질문으로 필요한 자료만 최신 조회한다. 전체 업무 요약 질문에는 연결된 모든 범위를 조회한다. 대상을 알 수 없는 질문에는 확인 질문을 만들고 AI를 호출하지 않는다. 기존 원장에서 발송 확인된 지난 7일 정기 보고의 요약도 맥락으로 복원한다. 과거 맥락을 최신 사실로 사용하지 않는다.
- `sources.mjs`: 기존 Chat OAuth/페이지 조회 방식, `recurring.mjs`의 조회·회차·휴일 계산, 연결현황의 계약·라이센스·복지·차량 파서를 재사용한다. 고정비 계산은 기존 `build-evidence.mjs`와 같은 방식으로 `runner.mjs`의 순수 계산 구간만 제한된 VM에서 읽어 사용한다. 실행기 main/발송/원장 코드는 실행하지 않는다. 계산 구간 경계가 바뀌면 차단한다.
- 복지는 A·E열만, 차량은 계약서(DB) C·E·I·Q만 읽는다. 훈련생·건강검진·Gmail·미연결 일정은 읽지 않는다. Chat 업무 참조는 기존 지정 2개 공간만 읽고 그 커서를 쓰지 않는다. 원본 조회 실패/미설정은 확인 불가다.
- Antigravity는 대기 질문이 있을 때만 1회 호출한다. 사실은 최신 조회의 ID로만 선택하고, 화면에는 원본에서 가져온 문장과 출처 ID를 그대로 표시한다. AI 제안은 검토/사전 준비의 고정 문구 중 선택한 미실행 제안으로 구분하며 AI 자유 서술과 미납/미처리/누락/완료 단정을 차단한다. 긴 질문/자료는 프롬프트 한도에서 차단하거나 일부 자료 제외를 명시한다. 범용 자율 에이전트나 도구 실행 대화는 구현하지 않는다.
- 신규 제안은 AI 호출 없이 서로 다른 원본의 동일 대상 또는 동일 확정 날짜를 연결해 최대 3개 검토 후보를 만든다. 최근 7일 발송 원장에 `sent`인 정기 보고 CHAT 본문과 비교하며, 관련 대상이 이미 등장하면 보수적으로 제외한다. 과거 후보와 같은 근거/내용도 제외한다. 보고 파일이 없거나 읽기 실패면 생성 보류다. 후보 자동 발송 경로는 없다. 자유로운 의미 유사도 기반 발굴은 포함하지 않는다.

## 운영 보호와 제한

KST 09:00–11:15 / 15:30–17:45 및 기존 원장에 `generating`/`sending` 항목이 있으면 대화 생성/발송을 대기한다(오전 09:30/오후 16:00 및 재시도·최대 실행시간 보호). 생성 중에도 1초마다 확인해 중단한다. 기존 원장은 읽기만 한다. 질문 수집은 계속 가능하다. 원장이 없거나 손상되면 처리를 멈춘다. 정기 보고의 결과 불명 항목이 남아 있으면 대화도 보수적으로 대기한다.

`maxDailyCalls: null`은 사용자 승인한 **필요시 호출** 정책으로 자체 일일 횟수 제한을 두지 않는다. 숫자 1~20은 선택적인 일일 상한으로 계속 지원한다. 질문이 없을 때는 AI를 호출하지 않는다. 모든 신규 대화 AI 실행에 세션 설정 `useG1Credits: false`를 강제해 구독 한도 초과 시 크레딧으로 전환하지 않는다. 사용량은 호출 전에 저장하며 실패도 계산한다. 한도/실행/근거 검증 실패 질문은 `blocked`로 남기고 해당 KST 날짜의 추가 AI 호출도 멈춘다. 정기 보고 보호로 생성이 중단된 질문만 대기로 되돌린다. 별도 쿼터가 없으므로 이 보호만으로 구독 잔여량을 보장하지 못한다. 보류 질문과 발송 결과 불명의 재처리는 원인·접수 여부 확인 후 별도 승인 작업으로 남긴다. 시간대 외 수동 정기 보고가 새로 시작되는 순간에는 최대 1초의 감지 지연이 있다.

`--once`/`--loop` 기본값은 답변을 로컬에 저장하는 미리보기다. 후보도 로컬 상태에서 확인한다. `--send`는 명시적인 사용자 승인 후에만 사용하며, 로컬 `deliveryApproved: true`도 필요하다. 저장된 답변 1개를 기존 웹훅으로 새 메시지로 보낸다(질문 스레드 답장은 이번 최소 구현에 포함하지 않는다). 기존 웹훅 URL은 수정하지 않고 대상 공간 일치를 확인한다. 응답 ID를 얻지 못했거나 중단되면 `unknown`으로 보존하고 자동 재발송하지 않는다. 발송 직전에 같은 원본을 다시 조회해 근거 해시를 비교한다. 변경되면 발송하지 않고 재생성 대기로 돌린다. 조회와 발송 사이 외부 변경까지 원자적으로 막을 수는 없다.

## 운영 PC에서만 준비할 설정 — 저장소에 넣지 말 것

기존 `%USERPROFILE%\.aiboot\config.json`, `chat-token.json`, 기존 OAuth 클라이언트/Sheets 인증과 `googleapis` 설치를 읽는다. 토큰 재승인·기존 설정 수정은 수행하지 않는다. 별도 `%USERPROFILE%\.aiboot\assistant.json`의 필드:

| 필드 | 의미 |
|---|---|
| `space` | 사용자 확인을 받은 대화 공간 `spaces/…`. 기존 업무 참조용 `chatSpaces`와 겹치면 실행 차단 |
| `owner` | 질문을 허용할 본인 `users/숫자`. 표시 이름/이메일 추측 금지 |
| `startAt` | 최초 질문 수집 시작 RFC3339 시각. 기존 과거 메시지를 무단 처리하지 않도록 명시 |
| `maxDailyCalls` | `null`: 필요시(자체 횟수 제한 없음). 숫자 1~20: 선택적 일일 상한. 구독 한도·보고 보호는 항상 적용 |
| `deliveryApproved` | 기본 생략/false. 실제 발송 승인 이후에만 true |

토큰 계정은 대화 공간 멤버여야 한다. 기존 웹훅은 이 공간에 등록되어 있어야 한다. 이 조건과 실제 운영 버전은 클라우드에서 미검증이다. 업무 참조용 공간을 대화용으로 전환하거나 신규 공간/웹훅을 만드는 작업은 자동으로 하지 않는다.

## 검증·실행

```sh
node --test integrations/chat-assistant/tests/*.test.mjs
node integrations/chat-assistant/cli.mjs --once
node integrations/chat-assistant/cli.mjs --once --propose
```

실행 명령은 운영 PC 승인 후 사용할 안내다. 현재 작업에서는 모의 테스트만 실행하며 운영 CLI/AI/Google API/웹훅은 실행하지 않는다. `--loop`는 60초마다 조회하며 Windows 스케줄러를 등록하지 않는다. Chat 조회 자체는 AI 호출이 아니다. 기존 구독·PC를 쓰고 신규 유료 API/서버/터널은 요구하지 않지만 실제 계정 쿼터·권한·비용 조건과 Antigravity 로그인/JSON 출력은 운영 PC 검증이 필요하다.
