# 다음 단계 — 개발 전 검증

## 1. Google Chat 양방향 연결 가능성 (우선)

- 사용자 전용 보고 수신 + 사용자 지시·질문·승인 회신 가능 여부 조사.
- 회사 계정의 권한, Chat 앱 또는 봇 등록 조건, 비용을 확인.
- 실제 전송은 사용자 명시 승인 후 테스트.
- 직원 Chat 공간 분석은 2단계로 유지.

## 2. 보고 자동 실행 가능성

- 오전 09:30 전체 브리핑 및 오후 16:00 요약.
- 주말, 공휴일, 종일 휴가 제외. 반차 보고 유지. 복귀 시 누적 사항.
- 기술적으로 실행할 수 있는지 확인하되 아직 자동화 생성 금지.

## 3. 실무 상태 데이터

- 관리비 시트 노란색 셀 배경 조회 가능 여부 확인.
- 노란색은 지출결의 제출 표시로만 사용.
- 다우오피스 전자결재·휴가 접근 가능 여부 별도 확인.
- 미납/결재 완료는 근거가 있어야 판단.

## 4. 첨부파일 실패 사례 분리 검증

- Excel 형식 읽기 문제, 보안 HTML, PDF 읽기 문제를 구분.
- 처음부터 별도 로컬 프로그램을 만들지 않고 반복 실패 업체에만 제한적으로 적용.

## 5. 운영 여부 결정

- 실제로 업무에 가치가 있는지, 추가 구현이 필요한지 검증 결과를 바탕으로 결정.
- 현재는 서비스 개발, 대시보드 구현, 배포, 유료 API 연동 모두 시작하지 않음.

## 최신 우선순위 변경 — AI비서 중심 (2026-10-30)

후속 전체 23건 자동화 가능성 평가에 따라 **3건 자동화 / 20건 사람 개입 필요**로 방향 수정. 추가 자동화 자체를 우선 실험하지 않는다.

1. 전체 23건 업무 목록에 **자료 확인 경로, 사용자 직접처리 요청, AI의 후속 보조/보고 역할**을 연결한다. '자동화 불가'와 '업무 관리 제외'는 다르다.
2. 오전 09:30과 오후 16:00 보고를 **AI비서형**으로 정의: 할 일·직접처리 요청·기한·차액·결과·대기 내용을 포함. 'AI가 전부 수행했다'는 표현을 금지한다.
3. Gmail, 외부 사이트, 카카오톡, 전자결재 등 접근이 불가능한 구간은 사용자가 실행하여 제공하는 정보만 근거로 다음 단계를 진행한다.
4. 보고가 실제로 유용한지 검증 후 Google Chat 양방향 전송과 일정 트리거 가능성을 별도로 확인한다. 실제 전송은 승인 전 금지.
5. 3건 자동화 가능 업체 명단과 20건 제한 원인의 세부표가 **추후 확보되면** 검증 기록을 보완. 이 정보가 없더라도 기존 23개 업무의 비서형 보고 구조는 기획 가능.

위 '최신 우선순위 변경'은 앞선 본 문서의 사이트 자동화 검증 제안보다 우선한다.
