## 1. 목적과 범위

AIBoot은 **고정비 완전자동처리 봇이 아니라 경영지원 업무를 지원하는 AI비서**. 사용자의 후속 평가 결과 원본 23건 중 **현 조건에서 자동화 가능 3건 / 사람 개입 필요 등 자동화 어려움 20건**. 3건 명단은 이 대화에 전달되지 않았으므로 추정하지 않는다. 이 평가는 과거 청구서 표본 5건(비교 성공 1건)과 별도의 검토다.

- 원본 [MS] AD_관리비 내역 → [JP매월 지출](https://docs.google.com/spreadsheets/d/1za_CvtiImh51W9J_YzmY146rf7FaQ2oKz-3eHq8wiIo/edit#gid=695174831) — **14~36행, 2026년 23개 항목**.
- **2026-10 이지화물 이용 종료 및 최종 정리 완료**: 원본/이력은 유지하고 **2026-11 이후 활성 업무 요청과 정기 보고에서 제외**. 따라서 활성 항목 22개.
- **매장 안전관리자**: 원본에 유지. 사용자 지시에 따라 청구서 확인 업무에서는 제외. 활성 항목 수(22)와 '실제 청구서 확인 추적 대상'(21)을 혼동하지 않는다.
- Google Sheets, Gmail, 카카오톡, 외부 사이트, 다우오피스 전자결재·휴가, Google Chat 보고 등 기존 도구를 활용. **이 문서는 새 프로그램 구현 승인이나 자동화 실행 지시가 아니다.**

## 3. 업무 단계별 역할

| 업무 단계 | AI비서 | 사용자 |
|---|---|---|
| 회차 산출과 일정 확인 | 업체별 사용기간/청구주기/납부예정일로 확인할 업무 구성 | 예외/실제 변동일 정정 |
| 청구서 확보 | 접근 가능한 Gmail·파일 읽기, 사용자가 준 파일 분석 | 인증·사이트 로그인·자료 다운로드·카카오톡 파일 저장 |
| 청구서 대조 | 업체·사용기간·부가세 포함 금액을 시트 동일 회차와 비교 | 자료 부족 또는 판단 요구 시 확인 |
| 불일치 | **청구금액 / 시트 금액 / 차액만 보고**, 원인 단정 금지 | 차액 처리 판단 |
| 시트 입력 | 대상 셀 확인, 사용자 **승인 후** 입력 가능한 환경이면 수정·재조회 확인 | 수정 승인, 필요 시 직접 입력 |
| 지출결의 | 노란색 **제출 표시만** 확인 | 실제 결의 제출 및 처리 회신 |
| 납부 확인 | 실제 증빙/사용자 확인에 따라 **해당 회차만** 상태 반영 | 계좌 출금·결제·증빙 및 완료 확인 |
| 보고 | 사용자 해야 할 일·기한·대기 이유·완료·다음 조치 정리 | 보고에 회신해 변경 사항 제공 |

**금지되는 추론:** 시트 공란 ≠ 미청구/미납, 노란색 없음 ≠ 미처리, 노란색 있음 ≠ 승인/출금, Gmail 검색 안 됨 ≠ 미수신, 금액 일치 ≠ 납부, 결제일 도래 ≠ 미납.

### 회차별 상태 필드 (운영 개념, 실제 DB/시트 신규 생성은 하지 않음)

업체 / 사용 시작일 / 사용 종료일 / 청구 대상기간 / 수신·확보처 / 청구금액 / 원본 시트 대상월·금액 / 비교 결과 / 지출결의 제출 표시 / 승인 여부 / 납부 여부 / 실제 납부 확인 근거 / 다음 확인일 / 사용자에게 요청할 내용 / 마지막 변경일.

서로 다른 회차의 완료를 혼동하지 않기 위해 **업체+사용기간**을 구별한다. 이후 전자결재, 승인, 납부를 한 가지 '완료'로 합치지 않는다. 시스템이 이미 이 상태들을 영속 저장한다고 주장하지 않는다.

## 4. 정기 보고 운영 — 업무 비서형

**평일 09:30 오전 브리핑 / 16:00 오후 요약**. 주말·공휴일·종일 휴가는 건너뛰고, 반차는 보고 유지. 복귀 후 누적 사항 요약. 메일 도착마다 알림을 보내지 않고 묶어서 보고한다. 다우오피스 휴가 확인 연동은 아직 검증하지 않았다.

**오전**: 오늘/다가오는 실제 청구 회차, 기한, 제공 자료, AI가 조회·대조할 것, **사용자가 인증·다운로드·결재·납부 확인할 것**. 사용자가 이미 납부 완료라 확인한 생각공장 2026-09 사용분을 신규 납부 요청으로 재등장시키지 않는다.

**오후**: 오늘 *실제로 확인된* 변화만 완료·대기·지연(확정 근거 필요)로 보고. 오전 보고에 있던 일을 근거 없이 완료 처리하지 않고, 회신이 없다는 이유로 미완료 단정하지 않는다. 다음 근무일로 필요한 확인만 인계.

**예시 문구 — 실제 보고가 아님**

- 오전: '베네피아 [해당 사용월] 청구서 확인을 위해 인증 필요. 사용월/납부일 확인 후 시트 비교 진행.'
- 오후: '사용자 회신: [업체·회차] 지출결의 제출 완료. 실제 납부 여부는 별도 확인 필요.'
- 과거 완료: '생각공장 2026-09 사용분은 사용자 확인 납부 완료. 추가 납부 요청 없음.'

## 7. 향후 변경 관리

- 이 문서가 **고정비 관련 우선 참조 기준서**이며 다른 문서의 과거 메모/질문보다 우선한다.
- 변동이 생기면 **업체명·적용 시작 회차·이전 규칙·신규 규칙·확인 근거**를 기록하고 변경한다.
- 원본 스프레드시트·첨부 청구서 및 사용자 인증 정보는 GitHub에 업로드하지 않는다.
- 사용자가 별도 지시하기 전까지 Google Chat 발송, 시트 수정, 결제 등 실제 업무 실행은 하지 않는다.
