# AIBoot — 전사 경영지원 업무 누락 방지 비서 v1

> 2026-11-03 확장 기준. **고정비 특화 → 경영지원 업무 전반**. 사용자 확정: 매일 오전 09:30/오후 16:00 Google Chat 보고; Codex·Antigravity 2026-11-04~11-10 독립 병렬 비교 중. 이 문서는 범위/설계 문서이며 신규 작업 등록·업무 메시지 발송·시트 수정은 아니다.

## 목표
- 사용자가 이미 사용 중인 Google Sheets, Gmail, Google Calendar, 다우오피스 등 **원본 도구를 유지**한다.
- **일간·주간·월간·분기·반기·연간 및 사건발생형** 업무의 예정·누락 가능성·예외를 통합 감시한다.
- 주기가 다르다고 별도 정기 메시지를 무수히 발송하지 않는다. 오전 09:30 오늘 할 일/다가오는 일/대표 판단; 오후 16:00 오늘 근거 확인된 완료/남은 일/다음 근무일. 기본 하루 2회.
- 대상: 경영지원 담당자 1명. 승인 없이 메일 발송, 파일 수정, 지급, 결재, 일정 추가, 회사 데이터 외부 제공 금지. 민감한 직원 생일, 복지 내역, 사내 계약서는 GitHub와 LLM 보고서에 원문 노출하지 않는다.

## 공통 업무 레코드(내부 데이터 설계)
- `task_id`(영속 식별자), `category`, `title`, `owner`, `source_uri`, `source_record_id`, `source_verified_at`
- `recurrence` (`daily|weekly|monthly|quarterly|semiannual|annual|event|one_off`), `occurrence_id` (회차 단위), `period_start/end`
- `action_due_date`, `lead_days`, `notify_after`, `calendar_rule`, `holiday_policy`, `criticality`, `next_check_at`
- `evidence_type` (`sheet_value|sheet_color|mail|calendar|contract|user_confirmation`), `evidence_ref`, `last_evidence_at`
- `internal_stage` (자료확보/대기/결재 등 상세 단계는 내부만), `report_state` (사용자에게는 '처리할 일' 또는 '완료' **두 구분**), `certainty`, `exception_reason`
- 회차가 넘어가도 이전 완료를 재사용하지 않는다. 증빙이 없으면 `완료` 추정 금지. '처리할 일'은 '미납/지연'과 동의어가 아님.

## 보고 정책
1. 입력은 원본 시스템의 사실과 사용자 승인 회신; **보고 생성 자체로 업무 상태를 변경하지 않음**.
2. 기본 Chat 본문은 간략. 오전=오늘 업무·다가오는 일정·판단 사항 / 오후=오늘 새로 확인된 완료·오늘 남은 일·다음 근무일. 각 항목 1줄, 중요 업무 3~5건 우선.
3. 일간·주간·월간·분기·반기·연간은 **판단 윈도/집계 기간**이지 전부 별도 알림 채널이 아님. 월초·분기초·반기초·연초의 추가 확인 항목은 기존 브리핑에 포함. 별도 요약은 사용자의 명시적 요청일 때만.
4. 중복 억제: `task_id+occurrence_id+report_date+slot+agent`; 동일 상태 반복 보고 금지. 단 임박 기한/새 근거/위험도 상승 시 재알림.
5. 장기 선행 알림(예시 설계값, 계약별 확정 아님): 계약/교육은 충분한 사전기간을 계산하고, 실제 사내 통지 기한·법정기한을 우선.
6. AI가 자료에 접근하지 못했을 경우 '미수신/미완료'가 아닌 '확인 필요'와 접근 불가 사유 표기. 사용자 행동 요청은 정말 필요한 항목만.
7. 정보보호: 복지 포인트 개인별 사용내역, 생일, 휴가·건강 정보, 계약서 조항 원문을 Chat 전체 공간이나 GitHub에 노출하지 않는다. 가능한 DM/제한된 스페이스와 집계·최소 식별정보 사용.
8. Codex와 Antigravity 7일 비교: 동일한 확인된 업무 목록/원본 스냅샷/보고 시간/권한으로 독립 수행; 비서다운 표현은 자유. **1차 비교 기간 중 새 모듈을 한쪽에만 적용하지 않음.**

## 데이터 저장 제안
- 원본 업무표는 그대로, 사용자 입력란 추가 금지.
- 현재 생성된 숨김 탭 `AIBoot_데일리마감`은 최초 고정비용으로 설계됨. 여러 영역의 이벤트 기록을 확장할 때는 기존 열을 임의 변경하지 말고 **레코드 버전/업무 ID/회차 ID**를 포함한 신규 스키마를 설계하고 이관 검증 후 활성화.
- 예정일 규칙은 한 곳에 두고, 원본 변경을 주기적으로 확인. 원본에서 사실이 확인되지 않은 모듈은 조회·보고에서 비활성화.
- 로컬 Windows 구독 CLI 실행은 **PC 전원/로그인 종속**. 메일·캘린더 접근 인증은 각각 검증. 기존 웹훅은 단방향 보고 전용, 양방향 Chat 앱은 별도 연결 미완료.

## 실행 단계
### A. 기존 테스트 유지
- 2026-11-04~11-10 Codex/Antigravity 동시 7일 비교: 새 모듈을 섣불리 켜지 말고 현행 고정비로 공정 비교. 원본 대시보드는 참조 금지.
- 두 AI의 비교값: 오판, 중요한 누락, 필요 없는 반복, 사용자에게 맞는 표현, 실행시간/실행 안정성.

### B. 비활성 확장 모듈부터 데이터 조사
- 회사 자료 중 **복지포인트, 생일자 지급 규정, 교육 이수표, 전체회의 일정, 계약 관리대장**이 실제 존재하는 위치/접근 가능 여부를 조사.
- 확인된 규칙과 회차/기한을 출처별로 정리; 확인 전에는 AI가 업무/일정을 새로 만들어내지 않음.
- 현재 연결된 계정 또는 회사 보안 정책이 접근 허용한 문서만 조회.

### C. 통합 업무 판정·보고 엔진
- 각 모듈은 `collect() -> normalize() -> evaluate() -> summarize()` 공통 구조. 기존 보고/중복방지/일정 예외 사용.
- 기존 7일 비교 끝나고 검증된 모듈을 **양쪽에 동일하게 적용**해 점진 확대.
- 전환 전 shadow-mode: 내부 분석만 생성하고 실제 Google Chat 발송하지 않음.
- 업무 원천 누락시 '출처 미연결'로 따로 기록; 무리한 가짜 업무생성 금지.

## 미결/필수 검증
- 복지·인사·교육·회의·계약 원본 시트/규정의 실제 위치·권한, 각 분야 정확한 마감 규칙.
- 데일리 마감 스키마의 확장 저장 경로와 회차 중복/원본 변경 이력 전략.
- 회사 계정 Gmail/캘린더/다우오피스 접근 가능성, Chat 스페이스 민감정보 보호.
- 2026-11-04~11-10 테스트의 전원 의존성 문제: PC 꺼짐 시 보고 없음; 이는 현재 보완되지 않음.
