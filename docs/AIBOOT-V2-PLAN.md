# AIBoot v2 — 로컬 웹 업무 비서 제품·기술 계획 (검토/승인 대기)

> 상태: **설계안, 미구현, 미배포, 운영 반영 없음** (2026-11-16). 현재 운영 정책의 유일한 기준은 [CURRENT.md](../CURRENT.md)다. 이 문서는 미래 v2의 사용자 경험·기술 검증 계획만 정리하며 정기 보고 실행기 프롬프트에 넣지 않는다. GitHub 문서와 실제 Windows 운영 PC 상태가 다를 수 있다. **이 문서가 현재 실행·설치·테스트 통과를 입증하지 않는다.**

## 1. 왜 만드는가 / 누가 언제 사용하나

- **사용자:** 경영지원 담당자 1명.
- **v1 실제 사용에서 확인된 효과:** 일간·주간·월간 반복 업무와 고정비·복지·계약서의 날짜를 반복적으로 여러 시트에 들어가 확인하는 부담이 줄었다. 지정 Google Chat 스페이스의 업무 보고·대표 지시도 요약·리마인드되어 누락 방지에 도움이 되었다. 이 효과는 사용자 실사용 피드백이지 정량 시험 결과가 아니다.
- **남은 문제:** 보고를 보고 나서 실제 업무를 처리하고 완료·보류 등을 기록하려면 원본 시트로 돌아가야 한다. 사용자는 단순히 원본 링크가 아니라 **보고 이후 처리 편의**를 원한다.
- **v2 핵심 경험:** 기존 Google Chat 보고는 그대로 받고, 별도의 **사무실 로컬 웹 화면**에서 대상·회차·근거를 확인한 뒤 승인된 상태만 편하게 처리한다. 필요할 때만 AI에게 질문한다.
- **언제:** 평일 09:30/16:00 기존 보고 확인 후, 업무 처리 시 PC·사내망 아이폰 접속; 채팅은 수시가 아닌 요청 시만 사용.
- **목표:** 업무 판단 지원 + 업무 처리 동선 단축. 자율 결제·결재·메일 발송, 전사 업무 시스템, 외부 공개 서비스는 목표가 아니다.

## 2. 확정된 제약과 현재 운영 보호

- 기존 **Windows 작업 스케줄러 → Antigravity CLI → Google Chat 웹훅** 정기 보고(09:30/16:00), 기존 3장 카드·판정 규칙·원장·재시도 정책 **유지**. 신규 웹 서버가 별도의 정기 발송을 하지 않는다.
- 최초 운영은 **사무실 Windows PC 로컬 서버 + 같은 사내 네트워크의 아이폰 Safari**. 사무실 밖 원격 공개, 포트포워딩, 외부 호스팅은 제외.
- **유료 AI API·유료 서버·카드 등록 금지.** CLI는 각각의 기존 로그인·약관·사용 한도를 확인하고, 사용 불가 시 유료 API로 자동 전환하지 않는다.
- 기존 Google Sheets가 사실의 원본. 원본을 AI 편의에 맞춰 복사하거나 중복 입력하지 않는다. 기존 6개 분야·필드별 제한·개인정보 제외 규칙은 [CURRENT.md](../CURRENT.md)와 [고정비 규칙](FIXED-EXPENSES-V1.md)을 우선한다.
- **AI는 사실·추론·확인 불가를 구별.** 기록이 없다는 이유로 미납·미완료를 확정하지 않는다. 쓰기 기능은 별도 승인 전까지 금지.
- 보안 정보·개인정보·실제 업무 원문을 GitHub, 브라우저 번들, 일반 로그에 저장하지 않는다.
- 기존 고정비 연결현황 v1은 동결 상태이며, 수정하지 않고 출력·판정만 재사용한다.
- 단계별 **백업 → 최소 수정 → 테스트 → 독립 검토 → PR → 사용자 승인 → 운영 PC 반영 및 실제 수신 검증**. GitHub 병합 ≠ 운영 적용.

## 3. v2 최소 기능과 화면

**웹 4영역(모바일 우선):** (1) 오늘: 최근 보고·확인 사항·발송 상태의 읽기 전용 표시, (2) 업무: 분야별 목록·정기 업무 회차/상태·상세 근거, (3) 채팅: 직접 선택한 모델로 요청 시 질문, (4) 기록: 실제 처리이력·확인 결과. PC에서는 사이드바, 아이폰에서는 하단 내비게이션 후보.

**단계별 범위**
1. **v2.0 읽기 전용:** 실제 운영 시스템과 격리한 Vue 화면·서버, 보고/회차/연결현황 조회만. 전혀 쓰지 않음. 기존 완료·보류는 이미 설치되었다고 전달받은 시트 메뉴를 사용(운영 PC에서 설치 상태 검증 필요).
2. **v2.1 채팅:** 정형 업무 조회는 Node.js의 검증된 함수로 처리; 모델은 사용자가 선택하고 필요할 때만 호출. 화면에서 '지원하는 명령'과 'AI가 해석한 의견'을 구분.
3. **v2.2 판단 보조:** 관련 원본의 허용된 최소 사실·출처를 첨부하여 비교·요약·후속 행동 제안; 자료 누락 시 답변 제한.
4. **별도 승인 후 쓰기:** 정기 업무의 업무ID+회차키+상태+근거 확인 → 사용자 승인 → 지정한 처리이력만 쓰기 → 재조회. 고정비·계약서·복지의 '완료'는 의미와 원본이 다르므로 하나의 공통 완료 버튼으로 처리하지 않음.

## 4. 기술 후보(구현 전 검증)

| 계층 | 우선 후보 | 적용 기준 |
|---|---|---|
| 브라우저 | Vue 3 + Vite + 반응형 CSS | 빌드 산출물만 로컬 서버가 제공. 아이폰 Safari·PC 지원 |
| 로컬 API | Node.js + Fastify | 정기 보고 프로세스와 분리, 요청 입력 스키마·동시성 제한 |
| 데이터 | 기존 Google Sheets API·업무 규칙 | 승인된 범위만 조회, 상태 변경 전 원본 재조회 |
| 재사용 | `recurring.mjs`, `operating.mjs`, `fixed-expense-flow` 판정 | 부작용 없는 함수만 재사용; 동결 기능 수정 금지 |
| 보고 사실 읽기 | 기존 보고·로그·ledger 읽기, 필요 시 `runner.mjs --test --dry-run --facts-only` 서브프로세스 검증 | **runner.mjs를 import 금지:** import 시 main 실행. facts-only도 일별 로그·공휴일 캐시를 쓸 수 있으므로 엄밀한 무변경 시험은 별도 전략 필요 |
| 채팅 선택 | Ollama(로컬 Qwen 소형 후보), Codex CLI, Claude Code CLI, Antigravity CLI | 실제 로그인·약관·응답·쿼터·데이터 외부 전송 범위 검증한 항목만 표시 |
| 추가 저장 | 먼저 기존 이력, 필요 시 `~/.aiboot/v2/` 로컬 별도 데이터 | 세션·감사로그만; 원장·업무 원본 중복 금지 |
| 보안 연결 | 사내 LAN 한정 HTTPS + 단일 사용자 인증·서버 세션 | mkcert는 **시험 후보**. 회사 단말 인증서 설치 승인·신뢰 설정, IP 변경/인증서 갱신 등 실제 검증 전 확정 금지 |

**의존성 위험:** 현재 실행기가 `google-sheets-mcp` 설치 폴더의 `googleapis`와 인증을 참조한다는 분석이 전달됨. v2 의존성 추가가 기존 실행기를 깨지 않는지 점검하고, 인증·라이브러리 분리는 운영 변경 승인 후 별도 검토한다. Node 24 설치 주장은 PC 확인 필요; 최소 버전과 패키지 잠금 파일을 빌드 단계에서 확정한다.

## 5. 선택형 AI 채팅과 안전장치

- **업무 사실 계산·회차·날짜·상태 판정 = 결정적 기존 코드.** LLM은 의도 해석·자료 요약·분석 제안만 담당. 모델이 변경 요청을 해석해도 서버가 대상·회차·근거·권한을 다시 검증한다.
- 모델 선택: 사용자가 **Ollama 소형 / Codex(GPT) CLI / Claude Code CLI / Antigravity CLI** 중 실제 검증된 모델을 직접 선택. 외부 CLI는 Google/Anthropic/OpenAI 서비스로 데이터를 전송하므로 각 서비스 정책과 회사 자료 전송 허용 범위를 확인해야 한다.
- CLI 실행은 격리된 임시 작업 폴더·권한 최소화·명시적 시간 제한·동시 호출 1건. 비밀값·임의 셸 실행·시트 쓰기 도구 금지. **CLI의 구독 인증이 웹 채팅 백엔드 사용을 허용하는지는 공식 조건 확인 전 '검증 필요'.**
- **사용량 보호:** 기존 보고와 계정 쿼터를 공유하는 Antigravity 및 Codex는 최소 09:15~11:00, 15:45~17:30 신규 채팅 호출 차단 후보. 이 차단만으로 하루/주간 구독량 고갈을 막을 수는 없으므로 계정 사용량을 검증할 수 없는 경우 사용자에게 수동 예산·상태 안내; 정기 보고 우선. Claude도 자체 계정 한도·자원 경합 검증.
- **Antigravity:** 현재 runner 기준 명령줄 프롬프트 길이 상한 32,000자; v2 채팅에서도 입력을 자르고 누락 여부를 알림. 긴 대화 전문/원본 전체를 넣지 않음.
- **Ollama:** 사무실 PC i3-13100, RAM 16GB, 외장 GPU 없음. 평소 80~90%, 창을 닫으면 60~70% 사용한다는 사용자 관측. 작은 모델(예: Qwen3 1.7B, 4B)을 **순서대로 시험한 후** 활성화. 매 질문마다 로딩 비용이 발생할 수 있음. `keep_alive`로 모델 메모리 해제, 동시 모델 1개·요청 1개, Ollama API는 `127.0.0.1`에만 바인딩. 모델 파일 크기와 실제 RAM 요구량은 다름.
- Ollama의 로컬 실행과 클라우드 모델을 혼동하지 않음; 클라우드 사용 금지 설정 및 모델·네트워크 동작 실제 확인. 근거 없는 응답, 모호한 회차, 누락된 원본은 '확인 필요'.
- 모델/서버 장애가 업무 조회·처리 및 기존 정기 보고에 전파되지 않도록 분리. Ollama 사용 시 Windows 메모리·페이징·CPU 사용과 정기 보고 시간 충돌 검증.

## 6. 사내망 접속·보안 기준

- 브라우저는 AIBoot HTTPS 웹 서버에만 접속. Google OAuth 토큰, CLI 로그인, Ollama 포트, 웹훅 URL 등은 서버 외부로 노출 금지.
- 아이폰 Safari의 인증서 신뢰와 HTTPS를 확인한 뒤에만 업무 처리·로그인 활성화. mkcert 자체가 신원을 인증하는 것은 아니므로 **로그인 + 서버 세션(HttpOnly/Secure/SameSite) + 세션 만료 + 로그인 제한 + 요청 위조 방지 + 변경 요청 검증** 필요.
- Windows 방화벽에서는 필요한 로컬 포트와 허용 네트워크/기기 범위를 최소화. 사내 Wi-Fi의 클라이언트 격리·IP 변경·IT 정책 확인. 회사 정책에 따라 사용자나 IT가 직접 승인·설정.
- **LAN 접속이 가능하다는 가정은 미검증.** 미검증 상태에서 HTTP 무인증 웹을 임시 운영하지 않음.
- 로그에 업무 원문·개인정보·비밀번호·토큰·프롬프트 전문 기록 금지. 단일 사용자라도 접근 실패/승인/변경 결과는 최소 감사 정보로 남김.

## 7. 운영 상태/문서 충돌 — 확인 전 사실 확정 금지

1. `CURRENT.md`는 유일한 **운영 정책**이므로 v2 내용으로 덮어쓰지 않는다. 현재 '화면 확장은 명시적 재지시 전 시작하지 않는다'는 규칙이 있으나 사용자는 v2 방향과 GitHub 최신화는 지시했다. **실제 개발/운영 확대 범위의 명시적 승인 여부는 단계별로 별도 확인**한다. 운영 정책 변경이 필요하면 보고 프롬프트에 영향을 최소화하는 좁은 문구로 별도 PR에서 승인한다.
2. GitHub `README.md`에는 11/06 운영 코드 `claude/chat-oauth-client` · `32577bb`라고 남아 있다. 제공된 검토 보고에는 **11/13 운영 PC는 main `8baaee3`**라고 되어 있으므로 운영 PC 실제 Git HEAD·스케줄러 경로를 다시 대조한 후에만 README를 정정한다.
3. `CURRENT.md`에는 정기 업무 시트 메뉴 '설치 전', E열 알림 시작 '운영 반영 대기'라고 쓰였지만, 제공된 검토 보고에는 완료되었다고 기록되어 있다. 실제 운영 PC와 시트 메뉴 확인 후 정책 문서 수정 여부 결정.
4. 11/13 16:00 첫 보고 검증 실패 후 16:15 재시도 발송, 11/16 09:30 실행 상태는 **전달받은 작업 보고의 진술**이며 현재 독립 검증되지 않았다. 실제 화면 수신·원장·로그를 확인할 것.
5. 현재 repo에 `package.json`이 없다는 분석은 v2 최초 의존성 추가 시 패키지 범위·운영 격리 필요성을 뜻함. 별도 앱 하위 디렉터리에 패키지와 lockfile을 두는 방향 우선 검토.
6. 스케줄러·웹훅·ledger·`CURRENT.md`·고정비 동결 규칙을 v2 초기 작업에서 수정하지 않는다.

| 3. 사실 조회 | 기존 업무 규칙을 변경 없이 연동 | 원본 조회와 실패 구분, ID·회차·링크 검증 |
| 4. 선택형 채팅 | 각 CLI/로컬 모델 단독 기능/약관/자원 시험, 보고 시간 보호 | 사용자 질문에 근거 답변, 정상 보고 최소 2근무일 확인 |
| 5. 쓰기 기능(별도 승인) | 먼저 테스트 회차만 검증, 중복/모호한 입력 거부 | 정확한 회차 한 곳만 기록, 재조회 성공, 사용자 승인 및 운영 테스트 |

**클라우드 검증 가능:** 저장소 코드, 모의 데이터 테스트, Vue 빌드, 인증/시각 정책 단위 테스트. **사무실 PC에서만 검증 가능:** 실제 체크아웃/스케줄러/계정 로그인/CLI 쿼터/시트 권한/메모리/아이폰 LAN+인증서/실제 보고 수신.

## 9. 승인되지 않은 작업

- 이 문서만으로 v2 구현, Windows 방화벽·인증서 설치, 시트 쓰기, CLI 자동 호출, 모델 다운로드, 배포, main 병합을 승인한 것으로 보지 않는다.
- 결제 수단 등록·유료 API·외부 서버 개설·GitHub에 회사 데이터 업로드 금지.
- 완료 판정은 **코드 작성 ≠ 테스트 통과 ≠ PC 반영 ≠ 실제 운영 수신 검증**으로 구분한다.
